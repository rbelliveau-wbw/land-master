The function copies the exported report action's Development type, code/date name, six approval rows, template categories and items, and HeavyJob prerequisite. Its historical all-budget approval Sort_Order backfill is omitted: creation only touches the new parent and children. The creator owner is added for the accepted Edit Owned creation permission. Category/item/approval read-back verifies the exact intended rows; errors retain a known parent ID. `check` reads existing rows and never inserts or repairs. Pre-write rejection is explicitly distinguished from an unknown/partial write. There is no transactional uniqueness guarantee across simultaneous server calls; the duplicate check and widget's busy guard protect routine use, and existing duplicates produce a review state.

Check, Wire and Purchase Order reuse the existing preview-only request composer. This change creates no purchase-order/check/wire records, submission APIs or approval routes.
