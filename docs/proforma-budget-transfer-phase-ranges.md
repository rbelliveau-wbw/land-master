# Creator Budget transfer phase-range repair

The enabled Production API exposed a native Creator planner discrepancy: valid integer Start_Phase/End_Phase values were rejected by the floor comparisons, while the widget computed all additional costs from the same returned context. Vista Real North → Belliveau Ranch excluded 18 valid rows and showed only the two base items per phase. A synthetic native Creator execution reproduced the rejection with a saved 1–4 range; the standalone Deluge playground and previous JavaScript adapter did not reproduce it.

`PF_Budget_Transfer_Plan` now converts both range endpoints to decimals after the Impact Fees override and before the existing bounds/integer checks. This matches the already-normalized saved phase/lot checks. The automatic reimbursement range is normalized too. No allocation rules, permissions, transfer tokens, record writes, or PF values change.

Restoring those rows exposed a second native failure: Production Custom API Hits recorded `Number of statement execution limit exceed Line:(331)`. The planner had scanned every destination Budget Item for every source cost in every phase. It now groups destination items by Budget once and indexes the selected phase's items by Cost_Code. Matching still requires exact Cost_Code and Department; duplicate matches remain ambiguous and templates remain excluded. The same eight numeric emptiness fields and Unit are checked in one expression rather than a per-field loop.

Changed files: the planner, `scripts/test-proforma-budget-transfer.mjs`, this note, PF module documentation, and the Creator handoff. The test adapter explicitly models the decimal boundary for floor comparisons and covers valid 1–4, 1–1, 3–4 and invalid/fractional ranges, 1,200 unrelated destination lines, same-code/different-Department lines, duplicate targets, and templates. No widget source changes; Production widget remains 1.80.60 and its immutable release/mapping stay unchanged.

Affected forms/fields: reads `Proforma_Item.Start_Phase`, `End_Phase`, `Category`, `Item_Name`, and existing pricing/application fields. No schema or stored source data changes. Existing destination fields remain the transfer contract's Budget header metrics, Budget_Item Preliminary amounts/rates/Description, category/parent Preliminary totals, and Project.Proforma. Custom API `PF_Budget_Transfer` keeps its existing binding and security configuration. Only `PF_Budget_Transfer_Plan` requires Creator promotion; `PF_Budget_Transfer`, PF Save, and unrelated workflows are unchanged.

Verification: native Creator synthetic preview before/after normalization; fixed totals, Lot rates, Impact Fees credit, edited destination quantity/note, fractional range and Specific Months exclusions. The native synthetic result is phase 1 total 565.00, later phases 562.50, all phases 2252.50, with only the two intentionally fractional/month-based rows excluded. `npm run validate` and `npm run build:pages` pass in an isolated copy of main plus these five files; concurrent unrelated shared-widget work remains outside this commit. The translated parity test also passes with 1,200 unrelated Budget lines. No actual Budget apply is used for verification.

Publication: the normalization-only planner was selectively published as Land Master 9.31. Creator's API Hits then exposed the statement-limit failure. The indexed planner was selectively published through Stage and Production as Land Master 9.32 on 2026-10-02; the promotion contained exactly one function component. Production widget 1.80.60, all field definitions, Custom API security/binding, and unrelated Creator workflows remain unchanged.

Production verification after 9.32: Refresh preview for saved Vista Real North → Belliveau Ranch returns `Ready to send to empty Budgets.` from the Production API. Phase 1 shows 20 Budget items, $8,669,872.50; Phase 4 shows 18 Budget items, $6,662,372.50. All four Budgets total $28,664,490.00. There is no Not Migrated group and Send is enabled. Only read-only previews and temporary destination drafts were used; no Budget transfer was submitted. Screenshot evidence is saved locally at `.tmp/budget-transfer-restored-9.32.png`.

Rollback: restore the prior planner from commit d6a99ec and promote it through Creator, or disable the dedicated transfer endpoint while reviewing a regression. Widget rollback alone cannot change the server allocation. Do not clear Budget data or run a transfer to undo this code repair.
