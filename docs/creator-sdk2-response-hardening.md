# SDK2 cross-widget response audit

The user's cross-widget bug instruction applies to every equivalent caller, not only the widget that first exposes a failure. Settings review found a native response gap in the earlier SDK2 paths. The canonical count/cursor reader checked code `3000` without rejecting an explicit native error/status failure; Land's mutation predicate also omitted status checking. Land and Budget did not yet require a single returned update/delete ID to equal the intended ID. These are actual-source fixture findings, not observed live Creator failures or evidence of a server authorization bypass.

The canonical reader now rejects truthy `error`, `success:false`, `status:error|failed|failure`, and failed nested native result envelopes. Count failure cannot begin paging, turn into zero, or publish a complete snapshot. Record business fields named status/error/success remain ordinary data. Identical adapter copies are adopted by Budget, Land Master, Insights, Gantt and the Settings candidate. Remaining SDK1 widgets adopt this tested adapter during their separate migrations.

Land's update and selected-row delete now require exactly one valid string ID matching the requested ID; add requires one valid string ID. Explicit failure flags cannot mark a change saved. An unsuccessful core refresh keeps the previous complete snapshot visible, but inline and bulk editing remain blocked until a complete fresh core snapshot commits. This prevents a retained snapshot from masquerading as current after a denied or incomplete refresh. The actual controller fixture covers failed refresh, blocked edits and successful retry.

Gantt and Settings require the exact destination ID and fresh persisted verification. Their native CRUD predicates now reject competing top-level results, duplicate or nested record results, and failure flags beside a returned record ID. Gantt's raw update helper and Settings' raw mutation helper are private; committing public actions must pass the readiness, captured-draft and verification flows. These local guards prevent accidental entrypoint bypasses; they do not replace Creator authorization.

Insights has no direct record writes. Its access parser additionally rejects grant-looking failed native envelopes, including malformed array wrappers, failed siblings beside a valid JSON permission leaf and contradictory permission leaves. Returned native failures retain their primary code and raw response. The actual startup/authorization/Refresh fixture proves that such a response cannot load either report model and that a subsequent valid authorization recovers. Native environment methods and current permission policy are preserved.

Budget attachment auditing exposed uncertain-upload cleanup/replay and shared busy-state problems. The correction keeps the typed FILE success contract separate from CRUD IDs, retains an uncertain child/file for read-only review, and blocks attachment deletion while an upload is unresolved. Existing preview-first and file permission contracts remain.

Actual Land editor, mapping and staged-phase flows also exposed a second-click duplicate-create risk after an unconfirmed insert. Captured create attempts now quarantine the affected draft. A known exact returned ID can recover only after a fresh matching record/payload read; a missing ID cannot be guessed from a name, code or same-sized result. Recursive comparison preserves structured field values rather than collapsing distinct objects to a string. Staged work stops at an uncertain child and retains unsent rows; confirmed rows retain their IDs. The importer keeps its separate Lot_Code uniqueness and complete-inventory checks.

Land also preserves the entire native response when a mixed result contains a failed item beside an applied-looking result. Classification inspects that full envelope, so a known failure code cannot discard the sibling and allow a second insert. Competing or nested results stay quarantined without a guessed ID. Actual editor, mapping and staged-phase tests confirm that repeated Save sends only one insert; a single definitive precommit rejection remains manually retryable.

Budget's mapping and actual shared-comment composer have equivalent scoped create guards. A confirmed mapping row records its returned ID before the next operation begins; partial failure cannot replay it. An uncertain row/comment retains the captured draft and blocks another insert, including dialog reopening. Its lean permission parser additionally checks malformed/failed known wrappers and conflicting leaves while retaining the full legacy degradation policy. These frontend locks cannot provide durable idempotency across a page reload; an unknown create without a usable ID needs review in Creator before another manual action.

The shared reader fixture exercises both count and records for eight malformed success envelopes, preserves raw responses, and ensures business fields are not confused with native response envelopes. Actual Land CRUD fixtures cover wrong IDs, duplicate confirmations, status failures and no replay. Gantt executes its actual update controller for the corresponding failure flags. Every affected source gets a new immutable release and a normal authenticated Development/Production check. Such normal checks do not establish live forced-failure, file-upload, reduced-role or every-workflow coverage.

Candidate versions are Budget `122.28.13`, Land `8.13.9`, Insights `1.5.40`, Gantt `1.1.5`, and Settings `1.3.3`. Earlier unpublished candidates were preserved privately, without modifying their immutable files. Their native gate results and rollback mappings are recorded in the [live ledger](creator-performance-live-ledger.md) after testing. No Creator schema, workflow, function or Custom API deployment is required for this frontend correction.

Two user-reported UI regressions require separate successors before this coordinated Production promotion. Budget `122.28.15` loads complete minimal comment/attachment summaries in the background without requiring a click and patches existing badges while keeping full detail deferred. Its predecessor 14 failed the native Dev gate because present empty lookup objects were treated as unreadable parents; 15 normalizes exactly empty objects, preserves unknown for missing or malformed data, and permits one complete full-field read when a projection omits a required key. Land `8.13.10` resolves Project names by exact loaded Project ID and supports native `zc_display_value` labels; relationships and total records remain unchanged. Native gates must explicitly check all visible badges, the correct project groups and preserved financial values, rather than infer those behaviors from matching record totals.
