Pro forma choices, modifications, import rows and assignment items, comment threads and attachment records are read only when their feature needs them. This is a frontend increment; existing Creator reports, forms, fields, APIs and business rules remain in use.

Pro forma choices request only `ID,Name`. The associated Project lookup supplies its existing display name before choices load. A picker stays in Loading or Retry until its complete read succeeds; it cannot change the association during a read or an active save. Full comparisons request full Pro Forma/header/child/detail reports. Projected choices never supply financial fallback values. Comparison callbacks keep their own model and navigation generation, and require complete published detail for every phase. A staged read withheld during a pending save shows Retry rather than financial rows; reopening after the save rereads the stale phase. Delegated comparison controls enforce the same barrier.

Modifications retain full fields and an explicit idle/loading/loaded/error state. Reads deduplicate, reject partial counted SDK results and publish only the current generation. Existing approval progress, targeted Check/Repair, duplicate guards, locks and ambiguous-write recovery are retained.

It refreshes modifications when already needed or explicitly required by a modification action. This prevents selecting stale category Final totals with a fresh approved status. Known writes invalidate their affected report groups instead of clearing unrelated transport reads.

Full detail reloads stage categories and items together and retain existing model bindings throughout the read. Publication checks active drafts/pending saves again immediately before replacing them, including sibling phases in the all-phases editor. A new edit started during a reload stays bound to its visible item. Deferred refresh is consumed after drafts settle, under the same navigation guard, and resets only after a complete safe refresh. Late callbacks cannot repaint another editor, comparison, imports workspace, attachment page or deep-link target. Mounted modification dialogs keep their typed fields and identity across save callbacks.

Comment/attachment/import badges show `…` for unknown/loading and `!` for a read error; only complete native reads produce a numeric count, including a confirmed zero. Counts patch mounted spans/labels rather than rerendering landing rows. Comment reads use their Project or Budget parent. Attachment activation uses the existing Budget criterion and preserves the legacy full-report local lookup fallback only after activation; preview still uses `Get_Budget_Attachment_Preview`. Import activation requires its complete rows and, for assignment users, complete full-field items. Failures provide Retry without presenting an empty completed feature.
