# Budget deferred features — 122.28.9

The first usable landing waits for complete Budgets, Subdivisions, Projects, five-field landing Categories and Approvals, plus the existing authoritative Lean access response. Pro forma choices, modifications, import rows and assignment items, comment threads and attachment records are read only when their feature needs them. This is a frontend increment; existing Creator reports, forms, fields, APIs and business rules remain in use.

Pro forma choices request only `ID,Name`. The associated Project lookup supplies its existing display name before choices load. A picker stays in Loading or Retry until its complete read succeeds; it cannot change the association during a read or an active save. Full comparisons request full Pro Forma/header/child/detail reports. Projected choices never supply financial fallback values. Comparison callbacks keep their own model and navigation generation, and require complete published detail for every phase. A staged read withheld during a pending save shows Retry rather than financial rows; reopening after the save rereads the stale phase. Delegated comparison controls enforce the same barrier.

Modifications retain full fields and an explicit idle/loading/loaded/error state. Reads deduplicate, reject partial counted SDK results and publish only the current generation. Revised matrices, Requests, check/wire balance composers, modification queue sections, create/submit/admin/decision actions, repair inference and modification-only deep links require complete modification data. Editors/composers also require complete phase categories and line items. Unavailable data never becomes zero modifications. Pending amounts remain separate: Final500 + approved50 - approved25 = Revised525; pending100 does not enter Revised. Existing approval progress, targeted Check/Repair, duplicate guards, locks and ambiguous-write recovery are retained.

Workflow refresh reads full Budgets/Approvals plus projected landing Categories as one coherent snapshot. It refreshes modifications when already needed or explicitly required by a modification action. An unavailable optional modifications report preserves fresh ordinary-track/landing values while Revised/request actions stay blocked; a modification-specific required refresh rejects. This prevents selecting stale category Final totals with a fresh approved status. Known writes invalidate their affected report groups instead of clearing unrelated transport reads.

Full detail reloads stage categories and items together and retain existing model bindings throughout the read. Publication checks active drafts/pending saves again immediately before replacing them, including sibling phases in the all-phases editor. A new edit started during a reload stays bound to its visible item. Deferred refresh is consumed after drafts settle, under the same navigation guard, and resets only after a complete safe refresh. Late callbacks cannot repaint another editor, comparison, imports workspace, attachment page or deep-link target. Mounted modification dialogs keep their typed fields and identity across save callbacks.

Comment/attachment/import badges show `…` for unknown/loading and `!` for a read error; only complete native reads produce a numeric count, including a confirmed zero. Counts patch mounted spans/labels rather than rerendering landing rows. Comment reads use their Project or Budget parent. Attachment activation uses the existing Budget criterion and preserves the legacy full-report local lookup fallback only after activation; preview still uses `Get_Budget_Attachment_Preview`. Import activation requires its complete rows and, for assignment users, complete full-field items. Failures provide Retry without presenting an empty completed feature. Modification queue arrivals patch only their mounted track sections.
