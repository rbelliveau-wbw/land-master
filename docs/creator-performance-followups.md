## Shared helper and security notes

The canonical reader keeps IDs as strings, validates expected counts and cursors, limits concurrent SDK work to three, isolates user/environment query keys, and avoids publishing raw rows or criteria in its telemetry. Scoped invalidation now removes only matching cache/in-flight entries and prevents affected older completions from repopulating cache; unrelated in-flight deduplication remains available. Fresh reads also prevent late older cache overwrite, and settled tokens are released. Behavioral tests passed and copies are synchronized into Budget 122.28.7, Land 8.13.4 and Insights 1.5.37 Development candidates. Current integrations keep TTL zero and do not cache permissions; no persistent-cache speedup is claimed. Invalidate before writes, retain invalidation on uncertain outcomes, keep eligibility/save verification fresh, and use controller generations to suppress stale UI rendering.

Local asset URLs now need both the mapped release and fetched-document fingerprint. All nine current source pages contain their configured version, and distinct currently mapped release versions have distinct HTML. The release-copy command now preflights config/version agreement, a requested HTML version marker and no matching HTML hash in prior release metadata before writing any target file. Helper-only future releases must update their HTML marker; immutable-target refusal is preserved. Temporary filesystem fixtures exercise both preflight and the actual CLI, including all nine current source formats; historical releases are not changed or revalidated. Some historical Contract/Tax/Gantt Stage pages lack their directory-version text. The fingerprint is a cache discriminator, not a security/authentication hash. Native `_lmh` presence verifies that the refreshed permanent loader includes this correction; earlier cached loader code cannot gain the new logic before being refreshed.

`LMData` includes `appLinkName` in its cache context. The three current SDK2 runtimes now expose that authenticated name, with an actual-runtime cache-isolation test; adopt the same runtime when migrating the six v1 widgets. Request history is capped at 500 entries; `requestCount` and response-size sum currently describe the retained window, not an unlimited session total. Keep bounded logs while adding cumulative counters if long-session metrics are required.

Permission flags and owner rosters are UI data. Preserve server-side authenticated actor/ownership checks on writes and native report read permissions. An additive summary or lean endpoint must not silently broaden user scope, authentication, environment reach, or writable record access. Retain attachment Custom API previews and ordinary-user file permission behavior. Avoid tokens, full access responses and private record/file contents in performance exports.

## Evidence required to close a followup

For each independent increment, record the changed files and immutable release, affected Creator forms/fields/functions/APIs, whether a backend publish is required, local tests, current live Dev/Prod observations, permissions/scenarios not tested, and the prior verified rollback mapping. Required repository checks remain `npm run validate` and `npm run build:pages`.

A controlled comparison should show complete unique counts and exact business totals first, then first usable render, number of count/read/custom calls, payload-size estimate, and render time. The helper measures serialized SDK responses rather than actual bytes transferred. Local transport fixtures cannot establish Creator latency or deployed permissions.
