## Next performance increments

1. **Remove unnecessary global work from Budget's landing.** Its initial `loadAll` still waits for complete Pro Forma choices and modifications (`widget.html:4653–4654`). The saved full permission function also scans every Pro Forma owner (`creator/functions/getUserAccess.dg:87–112`). The additive lean candidate keeps all flags and the roster while omitting that scan. Compare it to the current live full function, preserve OAuth/user scope and environment binding, then validate owner labels, Assigned to Me, comments and approval-recipient matching. Pro Forma still needs its owner map. Insights could later use a flags-only endpoint only after its authenticated actor and scope are established; no such endpoint is assumed to exist.

2. **Keep Budget landing totals exact while projecting less data.** The landing uses a hybrid total: Construction final only after its Construction approval; Development/Engineering final only after its Development approval; unknown departments final only after both. Empty category sets use the existing budget-level fallback. Do not substitute Revised/Modified/GP/HCSS totals. A first safe projection is the existing signed-in category report with `ID`, `Budget`, `Deparment`, `Prelim_Budget_Total`, and `Budget_Total`, preserving linked templates and zero values. Scope editor reads independently. An elevated summary API requires a proved record-read authorization rule; edit flags alone do not prove it.

3. **Defer Land related modules after its primary view.** `loadData` still gates the first render on fourteen reports plus choices (`widgets/land-master/src/app/widget.html:1130`). Derive a dependency list for the current Properties/Subdivisions/Companies view and load milestones, forecasts, lots, takedowns, additional items and Pro Forma pickers when their visible controls require them. Preserve counts and relationships by showing a loading/unavailable state until the authoritative scoped read finishes; never present unknown counts as zero. Add load generations so an older refresh cannot overwrite newer complete state. Import duplicate validation must keep fresh, complete reads of both selected-subdivision reports.

4. **Retain Insights history semantics while reducing its default barrier deliberately.** The adapter already uses a current/prior-year recent slice followed by complete history. Default Hide Empty is false, so the normal view waits for full history to include subdivisions with undated inventory (`sales-app.js:101`). This behavior is accurate and intentional. Any faster default requires an explicit product decision or a permission-preserving subdivision/inventory summary. Do not claim the recent-read transport alone made the default first view independent of history.

5. **Replace remaining v1 transports one widget at a time.** See [SDK v2 migration plan](sdk-v2-migration-plan.md): Gantt → Settings → Manage Lots → Tax → Contracts → Pro Forma. ## Shared helper and security notes

The canonical reader keeps IDs as strings, validates expected counts and cursors, limits concurrent SDK work to three, isolates user/environment query keys, and avoids publishing raw rows or criteria in its telemetry. Current integrations configure no TTL, so persistent report caching is not yet a demonstrated optimization. If TTL is introduced, invalidate before mutation starts and use fresh reads for eligibility/save verification. Keep canonical copies byte-identical through the sync script.

`LMData` includes `appLinkName` in its cache context. The three current SDK2 runtimes now expose that authenticated name, with an actual-runtime cache-isolation test; adopt the same runtime when migrating the six v1 widgets. Request history is capped at 500 entries; `requestCount` and response-size sum currently describe the retained window, not an unlimited session total. Keep bounded logs while adding cumulative counters if long-session metrics are required.

Permission flags and owner rosters are UI data. Preserve server-side authenticated actor/ownership checks on writes and native report read permissions. An additive summary or lean endpoint must not silently broaden user scope, authentication, environment reach, or writable record access. Retain attachment Custom API previews and ordinary-user file permission behavior. Avoid tokens, full access responses and private record/file contents in performance exports.

## Evidence required to close a followup

For each independent increment, record the changed files and immutable release, affected Creator forms/fields/functions/APIs, whether a backend publish is required, local tests, current live Dev/Prod observations, permissions/scenarios not tested, and the prior verified rollback mapping. Required repository checks remain `npm run validate` and `npm run build:pages`.

A controlled comparison should show complete unique counts and exact business totals first, then first usable render, number of count/read/custom calls, payload-size estimate, and render time. The helper measures serialized SDK responses rather than actual bytes transferred. Local transport fixtures cannot establish Creator latency or deployed permissions.
