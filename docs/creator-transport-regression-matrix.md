Common critical-error reporter fallback calls are POST JSON, so the GET argument bug does not apply to them. No SDK1 source has an object query_params call; its camelCase API/parameters shape must not be mechanically replaced before migration.

The vendor SDK2 sends `query_params` verbatim as `USER_API_OPERATION.queryParams`. The official [Custom API documentation](https://www.zoho.com/creator/help/js-api/v2/custom-api.html) does not specify its type or show a complete GET example. This supports checking real SDK behavior; it does not prove a missing URL prefix. The demonstrated Production access failure is the email/local-part-versus-Creator-session-username comparison. Preserve the existing backend session fallback for Production/Stage access and verify returned flags alongside complete data counts. Runtime email still isolates client identity/cache; it must not be rewritten into an assumed backend username.

## Scoped invalidation and targeted rendering: next increment only

The current canonical reader has no configured TTL in these integrations. `invalidate(predicate)` filters cached entries, but its generation and in-flight reset are global (`shared/creator-data.js:34`). This is safe for stale cache prevention; scoped invalidation is not yet a demonstrated performance optimization. Before adding TTL, use report/query generations so an unrelated invalidation preserves another report's deduplication and cached result. Invalidate affected scopes before a mutation starts; an uncertain or partial write must keep those scopes invalidated. A late read may resolve to its original caller, but its resource/navigation generation must prevent older state from being committed to the UI.

Start with an explicit dependency map. A note/header change should refresh the confirmed record and its visible row. Budget financial or approval changes need the affected budget's category/item/approval/modification dependencies and exact hybrid landing totals, plus Creator workflow outputs. Land lookup changes need the record and every displayed reverse relationship/count that uses the changed lookup. Import eligibility and save verification always require fresh authoritative reads. These scopes require business tests before reducing any reload.

Keep mounted panels and patch the affected row, badges and detail summary after persisted confirmation. Do not call full renderPanel while dirty/saving; it replaces inputs and can lose unsaved state. Preserve focus, current page/filter/scroll and disclosure state. Lazy datasets need explicit idle/loading/ready/error states so unknown totals never appear as zero, and navigation generations so late completion cannot reopen a dismissed editor. Measure avoided calls and render work after exact totals and complete counts are established. Implement only after the individual Production transport gate passes.

The measured Production Land transport run was dominated by reads: 7657 ms load versus 35 ms render, with a 7709 ms first usable mark and 42014016 estimated serialized response bytes. This single run suggests prioritizing deferred/scoped reads and projections ahead of broad rendering redesign; it is not a repeated benchmark or a measured saving from the next increment.
