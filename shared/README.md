# Creator data helper

`creator-data.js` is synchronized byte-for-byte into the six current SDK2 widgets by `node scripts/sync-shared-widget-data.mjs`. It provides complete counted/cursor reads, bounded requests, actor/environment/app isolation, scoped invalidation and telemetry. This change does not alter SDK payloads, schema, permissions, workflow defaults or the remaining SDK1 widgets.

`LMData.responseFailed(response)` inspects explicit native failure fields and only known `result`, `details`, `response` and `output` containers, including object/array or structured JSON values. A native non-3000 code, truthy error, failed status or success:false cannot hide beside a valid count/ID. Successful informational metadata stays valid. Cycles, malformed structured JSON or exhausted 128-node/16-depth bounds are unverified. Repeated references without a cycle remain valid. Report `data` and business fields are opaque; each CRUD validator explicitly checks its native acknowledgement data separately.

`LMData.failureCode(response)` preserves a non-3000 code from those containers and bounded rejected-error causes. Errors keep the original response; missing codes are not invented. Native record-ID/shape and persisted verification requirements stay in each widget's existing validator/controller.

Budget and Land reject failed acknowledgements without Saved or confirmed-success invalidation. Gantt retains its established fresh exact-date reconciliation: an applied effect can still become verified after an ambiguous acknowledgement if authoritative readback matches, without replay; denied/incomplete readback stays unknown and retains the mutation error. Settings retains the immutable draft/uncertain state until explicit read-only Recheck. No automatic create/write replay is added.

Regression commands are `node scripts/test-creator-data.mjs` and `node scripts/test-creator-envelope-propagation.mjs`, plus the affected widget suites. The propagation suite uses synthetic responses against actual canonical readers, Budget/Land native wrappers and Gantt/Settings whole-app handlers. It covers top/per-record/native-data failure containers, raw codes, normal direct/result-array acknowledgements, informational success and opaque business fields. These fixtures do not claim a captured native failed-container event or a live write/forced-error gate. Root owns release stamping, native Development gates and Production promotion.
